# 3. ডিলিট টেম্প ফাইল ও রিকভারি কনসেপ্ট

## উদ্দেশ্য
ফাইল ডিলিট হলে আসলে কী ঘটে, কখন রিকভারি সম্ভব, কখন সম্ভব নয় — এই থিওরি বোঝা।
এটি পরের চ্যাপ্টারে (winfr ব্যবহারিক রিকভারি) ঠিক-প্রত্যাশা তৈরি করবে।

## ৩.১ NTFS ডিলিট মেকানিজম

NTFS ফাইলসিস্টেমে একটি ফাইল ডিলিট করলে সাধারণত:

1. ফাইলটি প্রথমে **Recycle Bin**-এ যায় (যদি শিফট+ডিলিট বা সরাসরি সিস্টেম কল না
   হয়)।
2. Recycle Bin থেকে স্থায়ীভাবে ডিলিট করলে:
   - **MFT (Master File Table) এন্ট্রি**-কে "ফ্রি" হিসেবে চিহ্নিত করা হয় (ডেটা
     নিজে তখনও থাকে)।
   - ফাইলটি যে **ক্লাস্টারগুলো** দখল করে ছিল, সেগুলোকে "available for reuse"
     হিসেবে মার্ক করা হয়।
3. **প্রকৃত ডেটা তখনও ডিস্কে থাকে**, যতক্ষণ না নতুন কোনো ফাইল সেই একই
   ক্লাস্টারে লেখা হয়।

এই কারণেই ডিলিটেড ফাইল "রিকভারেবল" হতে পারে — যতক্ষণ ওভাররাইট না হয়।

## ৩.২ SSD এবং TRIM-এর প্রভাব

HDD-তে উপরের মডেল ভালোভাবে কাজ করে, কিন্তু **SSD-তে TRIM কমান্ডের কারণে
পরিস্থিতি ভিন্ন:**

- TRIM সক্রিয় থাকলে, ফাইল ডিলিট হওয়ার পরপরই SSD কন্ট্রোলারকে জানানো হয় যে
  সংশ্লিষ্ট ব্লকগুলো আর ব্যবহৃত হচ্ছে না।
- SSD কন্ট্রোলার প্রায়ই ব্যাকগ্রাউন্ডে (গার্বেজ কালেকশনের সময়) সেই ব্লকগুলো
  **আসলেই খালি করে ফেলে** — নতুন ফাইল না এলেও।
- ফলে SSD-তে ডিলিটেড ফাইল রিকভারির সাফল্যের হার HDD-এর তুলনায় **উল্লেখযোগ্যভাবে
  কম**।

```powershell
# TRIM স্ট্যাটাস চেক করা
fsutil behavior query DisableDeleteNotify
# 0 = TRIM enabled, 1 = disabled
```

## ৩.৩ ওভাররাইট হওয়ার ঝুঁকি

রিকভারির সম্ভাবনা কমে যায় যখন:

- ডিলিট করার পর সিস্টেম **ব্যাপকভাবে ব্যবহার হতে থাকে** (নতুন ফাইল লেখা,
  আপডেট ইনস্টল, ব্রাউজিং ইত্যাদি)
- অনেক সময় পার হয়ে গেছে
- ডিস্ক প্রায় পূর্ণ (কম free space মানেই দ্রুত ওভাররাইট হওয়ার সম্ভাবনা)

**সেরা অভ্যাস:** ডিলিট শনাক্ত হওয়ার সাথে সাথে সিস্টেমে নতুন কিছু লেখা বন্ধ করে
দ্রুত রিকভারি টুল চালানো।

## ৩.৪ কেন রিকভারি কখনোই ১০০% নিশ্চিত নয়

| ফ্যাক্টর | প্রভাব |
|----------|--------|
| SSD + TRIM | রিকভারির সম্ভাবনা তীব্রভাবে কমায় |
| সময় অতিবাহিত | যত বেশি সময়, তত বেশি ওভাররাইটের ঝুঁকি |
| ডিস্ক অ্যাক্টিভিটি | ডিলিটের পর ভারী ব্যবহার = কম সাফল্য |
| ফাইল ফ্র্যাগমেন্টেশন | ফ্র্যাগমেন্টেড ফাইল আংশিক রিকভার হতে পারে |
| ফাইলসিস্টেম টাইপ | NTFS vs exFAT vs ReFS — ভিন্ন আচরণ |

## ৩.৫ সংক্ষিপ্ত ফ্লো

```
ফাইল ডিলিট
   │
   ▼
MFT এন্ট্রি "ফ্রি" মার্ক + ক্লাস্টার "available" মার্ক
   │
   ├── HDD, TRIM নেই → ডেটা ডিস্কে থাকে → রিকভারি সম্ভব (ওভাররাইটের আগ পর্যন্ত)
   │
   └── SSD + TRIM সক্রিয় → ব্লক দ্রুত খালি হয়ে যায় → রিকভারি কঠিন/অসম্ভব হতে পারে
```
